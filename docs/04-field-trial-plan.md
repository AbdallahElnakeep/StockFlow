# خطة التجربة الميدانية — StockFlow

**الهدف:** إثبات أن النظام يعمل يوميًا في شركة توزيع حقيقية قبل البيع التجاري.

## 1. اختيار الشركة التجريبية
- شركة توزيع صغيرة/متوسطة: 1–3 مخازن، 2–5 مندوبين، 50–500 عميل.
- معيار القبول للشريك: صاحب قرار متاح أسبوعيًا + مستعد لتغذية راجعة يومية.
- التعاقد: مجاني 4 أسابيع مقابل بيانات الاستخدام والملاحظات.

## 2. قبل الانطلاق (أسبوع 0)
1. إعداد خادم (VPS 4GB) + نطاق + SSL + نسخ احتياطي يومي لقاعدة MySQL.
2. ترحيل بيانات الشركة: أصناف وعملاء وموردون وأرصدة افتتاحية (استيراد Excel).
3. جرد افتتاحي للمخزن الرئيسي عبر شاشة الجرد (يُثبت الرصيد الافتتاحي).
4. تثبيت APK على هواتف المندوبين + تدوين عنوان الخادم.
5. تدقاء تمهيدي: 60 دقيقة للإدارة + 30 دقيقة لكل مندوب (إنشاء فاتورة، تحصيل، مرتجع — لا شيء آخر).

## 3. أسبوعا التشغيل الموازي (أسابيع 1–2)
الشركة تستمر بنظامها الحالي **و** StockFlow بالتوازي:
- المندوب يسجل كل عملية في التطبيق مباشرة بعد كل زيارة عميل.
- مسؤول الإدارة يسجل المشتريات والتحصيلات في النظام يوميًا.
- في نهاية كل يوم: تسوية عهدة كل مندوب ومقارنة النتيجة بالنظام القديم يدويًا.

**بوابة الانتقال للمرحلة التالية:** مطابقة أرصدة المخزون والنقدية ≥ 98% لثلاثة أيام متتالية.

## 4. أسبوعا التشغيل الكامل (أسابيع 3–4)
- النظام القديم متوقف للعمليات اليومية (يُستخدم للرجوع فقط).
- كل الفواتير والتحصيلات والمرتجعات عبر StockFlow فقط.
- أول أسبوع: زيارة ميدانية واحدة للإدارة + اتصال يومي بالمندوبين.

## 5. مؤشرات نجاح التجربة (KPIs)

| المؤشر | الهدف | طريقة القياس |
|---|---|---|
| نسبة فوارق تسوية العهدة | ≤ 2% من قيمة العهدة، تنازليًا | تقارير التسويات — عمود الفرق |
| دقة أرصدة المخزون | مطابقة جرد أسبوعي ≥ 98% | جرد أسبوعي عبر النظام ومقارنة الفروق |
| تبنّي المندوبين | ≥ 90% من الزيارات مسجلة بالتطبيق يوميًا | عدّاد عمليات المزامنة لكل مندوب |
| زمن إنشاء فاتورة | ≤ 90 ثانية للمندوب | ملاحظة ميدانية (10 فواتير موزعة) |
| زمن تسوية العهدة اليومية | ≤ 10 دقائق لكل مندوب | توقيت عملية التسوية |
| أعطال حاجبة (blocker) | صفر | سجل المشاكل |
| رضا المستخدمين | ≥ 7/10 من المندوبين و 8/10 من الإدارة | استبيان نهائي (5 أسئلة) |
| دقة المديونيات | رصيد كل عميل يطابق دفاتر الشركة 100% | مقارنة عينة 20 عميلًا أسبوعيًا |

## 6. سجل المشاكل
كل ملاحظة تُسجل بصيغة: (التاريخ، المستخدم، الشاشة، الوصف، الشدة: blocker/major/minor، الحالة). مراجعة يومية خلال أسبوعي التشغيل الكامل.

## 7. قرار ما بعد التجربة
- **اجتياز كل المؤشرات** → التحويل لعميل مدفوع (باقة البداية) + إعلان حالة تجريبية مرجعية.
- **إخفاق مؤشر واحد** → أسبوعان إضافيان بعد الإصلاح على نفس الشركة.
- **إخفاق مؤشرين+** → مراجعة تصميم الميزة المعنية قبل أي تجربة جديدة.
